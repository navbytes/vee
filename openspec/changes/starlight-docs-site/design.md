# Design

## Decision 1 — Starlight owns `/guide/` and nothing else

The landing page is 40K of hand-written HTML over 18K of bespoke CSS: a wiping
hero headline, magnetic buttons, an animated fake menu bar driven by
`app.js`'s `IntersectionObserver`, and a screenshot gallery. None of it is
documentation, and none of it is what Starlight is good at.

So the site is split by purpose rather than by tool. `docs/index.html`,
`docs/compare/`, and `docs/assets/` are copied into the build output verbatim;
Starlight renders `/guide/` and inherits the same stylesheet variables so the
two halves do not look like different sites.

The alternative — porting the landing page into Astro components — was rejected
as a rewrite of working, finished design work, with a visual-regression risk on
the page that sells the app, in exchange for toolchain tidiness.

## Decision 2 — The prose does not move

`docs/_content/*.md` stays exactly where it is and becomes Starlight's content
collection root. Every existing cross-reference, every anchor, and every path in
`check_params.py`, `check_schemas.py`, and `build_reference.py` keeps working.

The one addition is Starlight's frontmatter (`title`, `description`), and the
values already exist — `build_guide.py`'s `PAGES[]` carries the title,
description, and nav label for all fourteen pages. That table becomes
frontmatter and a sidebar config, and is then deleted rather than rewritten.

## Decision 3 — The machine-readable forms are ported, not dropped

Change #95 published `llms.txt`, `llms-full.txt`, and a `.md` mirror per page,
and #96 made them CI-verified. Starlight provides none of the three. Losing
them would be a silent regression in exactly the capability this project most
recently invested in.

They become a small Astro integration that runs at build time over the same
content collection: emit each page's source Markdown beside its route, inject
`<link rel="alternate" type="text/markdown">` into each head, and write
`llms.txt` and `llms-full.txt` from the collection's frontmatter and bodies.
The `plugin-docs-integrity` requirements describe the guarantee rather than the
implementation, so they carry over unchanged in substance.

Starlight ships Pagefind, so `check_search_index.py` is deleted rather than
ported: the index is built from the pages at build time and cannot be stale.

## Decision 4 — Old URLs must keep resolving

`/guide/sdk.html` becomes `/guide/sdk/`. Those `.html` URLs are not internal:
every one of them is published in `llms.txt`, which was written for models to
fetch and cache, and they are in the README, the app, and the search index of
anything that has crawled the site.

GitHub Pages serves static files and has no redirect rules, so each old path
needs a committed stub emitting a meta refresh and a `<link rel="canonical">` at
the new location. Fourteen stubs, generated by the same integration from the
same page list, not hand-written.

This is the strongest argument for hosting on Cloudflare Pages instead, where a
`_redirects` file gives real 301s. The recommendation stays GitHub Pages —
the origin, the DNS, and the `CNAME` already work, and the change should not
also move hosting — but the swap is one workflow file if the stubs prove
unsatisfactory.

## Decision 5 — Deploy on push, verify on PR

Two jobs, not one. The Pages deploy runs on `main` only. `lint.yml`'s docs job
runs the same build on pull requests without deploying, so a docs change that
does not build fails the PR rather than the deploy.

The guide-freshness step (`build_guide.py --check`) and the search-index step
are deleted, because the artifacts they guarded are no longer committed —
staleness stops being a state the repository can be in. The parameter parity,
schema, constants, and link checks all survive untouched: they read
`docs/_content` and `docs/api`, never the rendered site.

## Risks

- **The zero-dependency policy.** Flagged in the proposal as the change's
  central tradeoff rather than buried here. It is the reviewer's call, not the
  implementer's.
- **Supply chain.** A docs toolchain pulls a large transitive tree into a
  repository that currently has none. Mitigations: it runs in CI and on
  developer machines, never on a user's; the lockfile is committed; Dependabot
  covers it; nothing it produces is executable by a reader.
- **Metadata regression.** The current pages carry canonical, OG, and Twitter
  tags, a skip link, and `aria-current`, which are better than Starlight's
  defaults. Task 6 verifies the new head against the old, tag for tag, rather
  than assuming a modern generator is a superset.
- **Build-time coupling.** Docs can now fail to publish for a reason unrelated
  to their content — a dependency break. Today a bad commit publishes a wrong
  page; after this, it can publish nothing. Pages keeps serving the last
  successful deploy, which makes that the safer failure of the two.
