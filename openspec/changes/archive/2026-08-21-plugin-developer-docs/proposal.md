## Why

Vee's plugin documentation is factually accurate but structurally and mechanically
incomplete. An audit of `docs/_content` against the source found that all 47 line
parameters, every `<xbar.*>`/`<swiftbar.*>`/`<vee.*>` header tag, and every injected
environment variable are correctly documented — but the **composable widget layout
tree** shipped in #55 (`VStack`/`HStack`/`Grid`/`Text`/`Gauge`/`Sparkline`/… plus
their layout, style, and font fields), which exists in `WidgetNode.swift` and in all
three SDKs, appears **nowhere** in the published guide. Two written pages
(`enterprise-store.md`, `roadmap.md` — 655 lines) are absent from `PAGES[]` in
`build_guide.py` and therefore never render. The site has no search over an 819-line
reference page.

The mechanism that let this happen is the real problem: the line-parameter list is
hand-maintained in **three** places — `LineParser.mapParams`, `Linter.knownParams`
(whose own comment states *"Hand-maintained, not derived"*), and the docs table —
with nothing checking that they agree. The repo already guards SDK fixtures against
the Swift parser and guards `docs/guide/*.html` against `docs/_content`; this is the
last unguarded copy of a shared contract, and it is the one that silently drifted.

## What Changes

**Documented surface (content)**

- Extract the Widgets section from `plugin-authoring.md` into a dedicated
  `widgets.md`, then document the composable layout node tree there — node types,
  layout fields (`align`/`spacing`/`columns`/`min_length`/`families`), `style`/`font`,
  and worked examples in all three SDKs.
- Extract a `debugging.md` page: `vee dev`, `vee lint`, `vee show`, `vee render`, the
  Debug console, timeouts, and exit codes as one authoring workflow.
  `cli-and-urls.md` remains the CLI reference.
- Publish the orphaned pages: add `enterprise-store` to `PAGES[]`; decide `roadmap`
  deliberately (publish, or relocate to `docs/design/` so it stops reading as a guide).
- Add an xbar / SwiftBar / Vee compatibility matrix to `migrating-from-swiftbar.md`,
  marking Vee-only params and tags so authors know what costs portability.
- Add a publishing path for plugin authors (catalog submission, trust-declaration
  honesty bar, self-hosted store), linking the now-published store page.
- Bring the Python and Go SDK READMEs to TypeScript parity on widget cards.
- Add a parse-diagnostics reference to `troubleshooting.md`.

**Machine-checked contract (behavior)**

- Publish JSON Schemas for the widget-card payload (`vee_widget: 1`) and the JSON
  output format (`{"vee": 1}`), and validate the existing SDK golden fixtures against
  them in CI.
- Add a drift guard that fails CI when `LineParser`, `Linter.knownParams`, and the
  documented parameter table disagree.

**Site**

- `docs/CNAME` → `vee.navbytes.io`, staying on GitHub Pages.
- Static search over the built HTML (Pagefind), plus dark mode, in-page table of
  contents, code-block copy buttons, `sitemap.xml`, and `robots.txt` — added to the
  existing stdlib generator and `app.js`.

**Explicitly not changing:** the documentation stack. No React, Docusaurus, VitePress,
or Starlight; no migration to Cloudflare Pages; no OpenAPI tooling (Vee exposes no HTTP
API). The site stays hand-written static HTML generated by a pure-stdlib script, and
the repo's zero-third-party-dependency policy is preserved — Pagefind is a build-time
binary, not a runtime dependency.

## Capabilities

### New Capabilities

- `plugin-docs-integrity`: The documented plugin-format surface is machine-checked
  against the implementation. Covers the published JSON Schemas for the widget-card
  and JSON-output payloads (validated against the SDK golden fixtures) and the
  line-parameter drift guard across parser, linter, and docs.

## Impact

- **Docs content** — `docs/_content/`: new `widgets.md`, new `debugging.md`, reduced
  `plugin-authoring.md` (~819 → ~450 lines), edits to `migrating-from-swiftbar.md`
  and `troubleshooting.md`. **25 inbound references** to `plugin-authoring.md`, 16 of
  them deep anchors (`#line-parameters` ×4, `#widgets` ×3,
  `#environment-variables-vee-injects` ×3), must be swept — `build_guide.py`'s
  `link_href` rewrites `foo.md#bar` to `foo.html#bar`, so a stale anchor renders as a
  working link to the wrong place rather than as a visible break.
- **Docs tooling** — `docs/scripts/build_guide.py`: `PAGES[]` entries, sitemap/robots
  emission, heading-level TOC data. `docs/assets/app.js` and the stylesheets: search
  UI, dark mode, copy buttons.
- **Schemas** — new schema files plus fixture validation wired into the existing test
  suite; no change to `WidgetCardParser` or `JSONOutputParser` behavior.
- **CI** — `.github/workflows/lint.yml` gains the drift-guard and schema-validation
  steps alongside the existing `build_guide.py --check` job.
- **SDKs** — `plugins/python/README.md`, `plugins/go/README.md` documentation only; no
  code change.
- **Infrastructure** — `docs/CNAME` plus a DNS record; GitHub Pages continues serving
  `docs/` from the default branch with no deploy-time build.
